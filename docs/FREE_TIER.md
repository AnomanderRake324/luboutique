# Бесплатные тарифы: лимиты, риски, резервные копии

Данные проверены 16.10.2026 по официальным страницам Supabase (supabase.com/pricing, docs «Project Pausing», Billing FAQ) и Cloudflare (developers.cloudflare.com/pages/platform/limits). **Условия меняются — перепроверьте перед запуском.** Никакого постоянного аптайма на бесплатных тарифах гарантировать нельзя.

## Supabase (Free)
| Что | Лимит |
|---|---|
| База данных | 500 МБ |
| Хранилище файлов | 1 ГБ (макс. файл 50 МБ; наш бакет ограничен 3 МБ) |
| Трафик (egress) | 5 ГБ + 5 ГБ кэшированного в месяц |
| Пользователи входа | 50 000 в месяц |
| Бесплатных проектов | 2 активных |
| Автоматические резервные копии | **нет** |
| Пауза | проект ставится на паузу после недели низкой активности |

**Пауза.** Если на сайте неделю почти нет запросов к базе, проект останавливается: сайт покажет «Не удалось загрузить данные», пока владелец не нажмёт Resume project в панели Supabase. Данные при этом не удаляются; по документации Supabase восстановить можно в течение ограниченного окна (в разных версиях документации указано 90 дней и 1 год — уточните на supabase.com/docs/guides/platform/free-project-pausing). После этого окна остаётся только скачать последнюю копию и файлы. Обычный трафик покупателей считается активностью, но гарантий нет: заходите в админку хотя бы раз в неделю. Платный план (Pro, от $25/мес) снимает паузу и включает копии за 7 дней.

**Превышение лимитов.** По Billing FAQ Supabase предупреждает о превышении, а при постоянном превышении вводит ограничения сервиса. Самое вероятное узкое место — трафик фото: оценка (не измерение) — если страница товара грузит ~10 фото по ~300 КБ, 5 ГБ хватит примерно на 1 500–2 000 таких просмотров в месяц. Фото сжимаются до 1600 px/WebP перед загрузкой, но следите за разделом Usage в Supabase.

**Картинки.** Платные трансформации изображений Supabase не используются.

Если лимит сборок исчерпан, новые деплои отклоняются до следующего месяца; уже опубликованный сайт продолжает работать.

## Коммерческое использование — **проверьте сами**
- Я не нашёл в источниках явного запрета коммерческого использования бесплатного плана Cloudflare, но и явного письменного разрешения тоже. Это вывод по сторонним обзорам и сообщениям на форуме Cloudflare, а не по тексту договора. Перед запуском бутика прочитайте актуальные Terms of Service на cloudflare.com/terms.
- Условия коммерческого использования бесплатного плана Supabase я отдельно не проверял; прочитайте Terms на supabase.com.
- Cloudflare ограничивает обработку платёжных карт на бесплатных сервисах — у сайта нет оплаты, только WhatsApp.
- Cloudflare развивает Workers Static Assets рядом с Pages: перед запуском посмотрите документацию Pages на предмет объявлений о будущем сервиса (я не проверял).
- Если условия не подходят, вариант Б: любой другой статичный хостинг — сборка (`dist`) работает где угодно; нужны только переменные `VITE_*` и перенаправление всех путей на `index.html`.

## Резервные копии и восстановление
- Автокопий на Free нет. В админке → «Настройки» → **«Скачать копию данных»** — JSON со всеми таблицами. Делайте раз в неделю и перед массовыми правками.
- **Фото в эту копию не входят.** Они в Supabase → Storage → бакет `media`; скачать можно через панель (по папкам) или Supabase CLI. Полноценная копия — оба шага.
- Автоматического восстановления из JSON в проекте нет: восстановление — это ручной импорт данных (SQL/скрипт разработчика). Это ограничение MVP.
- Исходный код лежит в GitHub — это копия сайта, но не данных.
- Миграции в `supabase/migrations` позволяют пересоздать пустую структуру в новом проекте.
